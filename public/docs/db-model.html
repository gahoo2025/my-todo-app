2026-08-22作成。列レベルの詳細は④ DBテーブル定義書を参照。このページは「テーブル同士がどう繋がっているか」の全体像に絞る。

1. ユーザー中心のスター構成

このアプリのSupabaseスキーマは、ほぼ全テーブルが user_id → auth.users.id の外部キーを持ち、Row Level Securityで「自分のデータしか見えない」構成になっている。 テーブル間の直接的な関連は少なく、auth.usersを中心にした放射状（スター型）のモデルが実態に近い。

3. モデル上の注意点

  • asset_balances / asset_summary / asset_holdings_history / asset_total_history / asset_category_history の5テーブルは、いずれも「資産額」を表すが役割が重複気味。特にasset_summaryは現在フロントのどこからも参照されておらず、レガシー（未使用）の可能性が高い。整理の余地あり（要確認）
  • 他の多くのテーブルも、正式なDDLはSupabase側が正で、このモデルはコード上のselect/insert列から逆引きした推定（詳細は④参照）
  • stock_master_list（このアプリ内）と gahoo-company の 銘柄リスト.csv（fundamental-3layer-screeningスキル）は同一概念だが別実体。将来的なデータ連携の余地がある
gahoo-company / product部署が管理。テーブルを追加・変更したら本ファイルと④DBテーブル定義書を合わせて更新すること。
